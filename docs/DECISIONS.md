# ShareLane — Decisions

Every decision made so far, and why. Add new ones at the bottom of the right table; never delete old ones. If a decision changes, mark the old one **Replaced by #N**.

- **Decided** = agreed by Manthan.
- **Proposed** = suggested by Claude and written into the design, but not yet confirmed. Needs a yes/no.

## Decided (2026-09-26)

| # | Decision | Why |
|---|---|---|
| 1 | Build our own hub rather than wiring agents together by hand (e.g. only Codex's built-in MCP server) | Want one tool that does routing, memory and safety together, and that others can use |
| 2 | **Any agent can orchestrate.** The orchestrator is whichever agent you're chatting with, chosen per task | Not a Claude-only tool; Codex or Gemini must be able to lead too |
| 3 | **Agent-neutral.** Any agentic coding CLI can be added; adding one should be config, not new code | Main goal of the project; makes it useful to everyone |
| 4 | **Subscription-only.** Agents run through their official CLIs with the user's own login. No API keys; ShareLane never touches login tokens | All of Manthan's agents are on subscriptions; keeps it within each vendor's terms |
| 5 | **Open source**, with content made around it. Personal use, no reselling | Multi-agent context loss is a common problem |
| 6 | **Memory is per project**, stored in the project (`.sharelane/`) | Each project has its own context |
| 7 | **Context is structured**: a short map + small topic chunks + task files + search, loaded only when needed. No giant single file | Avoid agents reading thousands of lines / hundreds of thousands of tokens |
| 8 | **Visual map of the context**, so every agent (and you) can see where each kind of context lives | Agents should know where to look |
| 9 | **Delegation is async**: returns a task ID straight away, the worker runs in the background | Long tasks would otherwise time out; you keep chatting with the orchestrator |
| 10 | **Git worktrees** for workers, so each has its own copy of the project | Strongest protection against agents overwriting each other |
| 11 | **Hub detects and stops conflicts** (two agents on the same files or the same task) | Agents editing the same files at once is a core risk |
| 12 | **Loop-safe delegation** (Claude → Codex → Claude can't go on forever) | Two-way delegation makes loops possible |
| 13 | **Permissions scoped per delegation/session** (e.g. "Codex may only touch the UI files") | Give each worker only the access its job needs |
| 14 | **Log usage** for every run, per agent | Every call counts against a subscription limit |
| 15 | **Agents check their own quota and write a handoff before running out**; another agent takes over. Reuse Manthan's existing quota-check approach from another project | Manthan has already built quota self-checks for Codex and Claude. (Corrects Claude's earlier wrong claim that agents can't see their quota.) |
| 16 | **Dashboard** to track all agents' activity and chats: local web page first, VS Code extension later | You need to see what background workers are doing |
| 17 | **Animated office view** (agents as characters at desks) as a later fun layer | Easier to understand at a glance; good for content |
| 18 | **Name: ShareLane.** npm package `sharelane` (was free on 2026-09-26) | Manthan's choice |
| 19 | **TypeScript on Node** | Manthan: "any language, easiest is best." Best-supported MCP toolkit; easy one-line install for users |
| 20 | **Not terminal-only.** The orchestrator can be a VS Code panel or a terminal; workers run in the background | Manthan works in VS Code |
| 21 | Gemini CLI may be installed on this machine | Manthan gave the go-ahead; planned for phase 7. **Replaced by decision 54:** Gemini CLI stopped serving personal accounts on 2026-06-18 |
| 22 | **Record and understand before building**; build in small phases, each explained, each with a "done when" check | This is a learning project |
| 23 | **Use Node's native ES modules**, with TypeScript's matching `NodeNext` module rules | Keeps ShareLane on one modern module system and matches the MCP SDK ecosystem |
| 24 | Agent MCP configurations identify their caller with the `SHARELANE_AGENT` environment variable; `whoami()` returns `unknown` when it is absent | A project-prefixed name avoids collisions and gives every adapter one simple, shared convention |
| 25 | Treat `.sharelane/notes.txt` as local runtime state and ignore it in Git; this does not decide whether future `.sharelane/context/` files are committed | Temporary shared notes should not create repository noise, while the context-sharing policy is still an open question |
| 26 | Keep a repository-level `GLOBAL_CONTEXT.md` work ledger, and use `AGENTS.md` to require compatible agents to read it before work and append a concise handoff before finishing | Future agents need one persistent, human-readable record of completed work, checks, current state, and the exact next step; concise entries avoid turning it into an expensive transcript |
| 27 | Use Node 24's built-in `node:sqlite` module, with WAL mode and a 5-second busy timeout, instead of adding `better-sqlite3` | A local probe proved that this Node build includes SQLite 3.53.3 with FTS5; the built-in module meets Phase 1 needs without another native dependency |
| 28 | Store each context chunk's metadata in a small ShareLane frontmatter header, with `covers-files` represented as a JSON string array; make `sharelane init` repeatable and protect existing chunk content | The files remain ordinary readable Markdown, no YAML dependency is needed, and rerunning setup is safe in an established project |
| 29 | Limit each chunk body to 12,000 characters and reject larger `update_chunk` calls with “compact this first” | This is roughly a few thousand tokens: large enough for useful topic context but small enough to preserve progressive disclosure |
| 30 | Commit `.sharelane/context/` Markdown files to Git, while keeping the SQLite database, WAL files, raw journal, and legacy notes local and ignored | The useful curated context should travel with the project and remain reviewable in diffs; replaceable indexes and noisy runtime logs should not create Git churn |
| 31 | Give every MCP tool accurate safety annotations, and pre-approve only the trusted local `sharelane` server in Codex's server-specific configuration | Codex otherwise blocks unattended MCP calls under its `never` global approval policy; the narrow server setting enables ShareLane without weakening approval rules for commands or other servers |
| 32 | Save a SHA-256 fingerprint of every chunk's covered file contents when the chunk is updated; retain the Git-timestamp check as a fallback for older chunks | Content fingerprints avoid falsely marking context stale when source and context are committed together, while still detecting committed, uncommitted, and newly created file changes |
| 33 | Use Node's built-in `node:test` runner during the early phases instead of adding Vitest | The built-in runner already supports the protocol, temporary-project, and multi-process tests ShareLane needs, so another development dependency would not yet provide enough value |
| 34 | Describe agent commands in `src/adapters/agents.yaml`, parse it with the `yaml` package, validate it with Zod, and always spawn argument arrays with no shell | YAML keeps adding an agent configuration-only; a maintained parser avoids a fragile home-grown subset; argument arrays prevent prompts containing quotes or shell symbols from becoming commands |
| 35 | Normalize Claude JSON and Codex JSON-lines output into one internal result, and keep raw run logs under ignored `.sharelane/runs/` | The rest of ShareLane can treat agents alike while local raw evidence remains available for debugging without creating Git noise |
| 36 | Persist delegated tasks in SQLite plus human-readable local files under ignored `.sharelane/tasks/`, and launch a detached ShareLane supervisor for each task | The caller gets a task ID immediately; the supervisor can still record the agent's completion, failure, session, usage, and log after the calling tool has returned |
| 37 | Store task conversation messages separately, and make `reply` resume the saved CLI session on the same task ID; guard final state changes in SQLite so cancellation wins races | Follow-ups retain the worker's context and remain easy to inspect, while a near-simultaneous worker exit cannot incorrectly overwrite a user's cancellation |
| 38 | Track the complete agent path for each task, allow at most three delegated levels, and reject a target already present in that path | A readable lineage makes both direct and indirect delegation loops detectable while still allowing useful short delegation chains; this accepts proposal P6 for Phase 2 |
| 39 | Prepend each new delegated session with its task ID, focused worker instructions, and the current generated context map; do not repeat that wrapper for resumed replies | A worker begins with enough project orientation to choose relevant context without loading everything, while follow-ups benefit from the context already held by the resumed CLI session |
| 40 | If an active task's detached supervisor PID no longer exists, report it as `orphaned` without mutating state during `status`/`wait`; allow explicit `cancel` to close it, and watch quick supervisor exits while the launcher is alive | A process killed by the operating system must not leave callers waiting forever, while read-only task inspection must remain truthfully side-effect free |
| 41 | On Windows, launch production task supervisors through the local CIM process broker under the current user; pass only executable paths, task ID, project root, and adapter-config path, while keeping direct detached spawn elsewhere and in custom-environment tests | Codex tears down descendants when its headless process exits even if Node marks them detached; the Windows broker creates the supervisor outside that tree while preserving the user's PATH, profile, and subscription-login files, without putting the delegated prompt into a shell command |
| 42 | Before `wait` returns a persisted final task state, refresh that task's human-readable Markdown file from the database; keep virtual orphan checks read-only | SQLite is the authority, but callers and people should not observe “completed” from `wait` while the readable task file still briefly says “running”; rewriting only persisted final states closes that race without turning orphan inspection into a mutation |
| 43 | Use token-efficient orchestration by default: do simple work directly; delegate only for clear specialist, review, parallel, or user-requested value; aim for roughly 25% or less fresh-token overhead versus a direct run; report cache separately; and add automatic warnings/budgets in Phase 5 | The calculator proof showed that repeated context and tool turns can make multi-agent processing much larger than the underlying task. A quantified target plus progressive disclosure and session reuse keeps today’s workflow disciplined, while Phase 5 will provide reliable cross-vendor measurement and enforcement |
| 44 | Run each Git-backed delegated task in a temporary external worktree on a unique `sharelane/task-*` branch; commit remaining edits, remove the checkout, and hand the branch/commit back without automatically merging | Isolation prevents physical overwrite, an automatic local commit makes cleanup recoverable, and review-before-merge is safer than silently changing the owner's branch |
| 45 | Give claims a 15-minute default TTL, refresh task claims automatically every 30 seconds, expose explicit `heartbeat`, and release claims at task termination | Live work keeps ownership with little prompt overhead, while crashed workers stop blocking others within a bounded time |
| 46 | Refuse conservative overlaps between claimed files/globs, and warn at 60% or greater word-set overlap between a new prompt and active tasks | Claims must favor safety when glob intersection is uncertain; prompt similarity is advisory because wording alone is not reliable enough to reject useful work |
| 47 | Install a shareable Claude `PreToolUse` guard for `Edit|Write`, and pair it with task Git polling plus a final diff for every agent | Claude's built-in edits can be blocked before execution, while detection still covers shell writes, Codex, and agents without compatible hooks |
| 48 | Persist collision notices in SQLite and append pending relevant notices to every successful ShareLane MCP reply | Separate stdio hub processes cannot push alerts, so the next normal tool call is the reliable delivery point |
| 49 | Accept an optional `scope` on `delegate`: up to 50 project-relative files, folders, or globs, normalized like claims (a trailing slash or existing folder becomes `folder/**`), persisted with the task, and reused by replies. Omitting it keeps whole-project behavior; empty lists and paths that leave the project are rejected | Existing callers keep working unchanged, while one normalized form lets claims, hooks, CLI flags, and Git checks all enforce exactly the same boundary |
| 50 | Make a task's scope its claim: pre-check it before creating the worktree, claim it in the same SQLite transaction that creates the task (and again on each reply), release it on every ending, refuse a scope overlapping another owner's claim, and refuse a scoped task's own claims outside its scope (glob claims only when equal to, or under, a `folder/**` scope entry) | Other agents are kept out before work starts, an atomic claim cannot race task creation, and a worker cannot unlock an out-of-scope edit by claiming it; the conservative glob-containment rule is simple to explain and never under-reports |
| 51 | Express scope through a whole-argument `{scopeArgs}` adapter slot with `scoped`/`unscoped` lists and `{scopePattern}`, `{scopeRoot}`, `{scopeExtraDir}` placeholders. Scoped Claude runs use `--permission-mode dontAsk` plus `Edit(pattern)`/`Write(pattern)` allow rules; scoped Codex runs root the `workspace-write` sandbox at the scope folder with `--cd`/`--add-dir` and remove the temp-folder write allowances; Codex always forwards ShareLane task variables to its MCP server with `env_vars` | Each CLI gets its strongest native restriction while adding an agent remains configuration-only. A real Codex run proved the temp-folder allowance otherwise makes the whole temp-located worktree writable, and forwarding task variables makes Codex claims task-owned and scope-checked in the main project database |
| 52 | Check scope in the Claude `PreToolUse` guard before the claim check, and make Git detection report out-of-scope paths as durable `scope_violation` notices plus a per-task `scope_violations` list, separate from unclaimed-edit notices | Claude built-in edits are stopped with a clear reason before they happen, while shell edits and agents without hooks still produce a specific, reviewable record |
| 53 | When saving a scoped task, write out-of-scope changes to `.sharelane/tasks/<task>.out-of-scope.patch`, restore those paths to the task's starting commit, and commit only in-scope work; notify the caller | An escaped write can never successfully reach the reviewable task branch, but its content is preserved as evidence instead of being silently destroyed |
| 54 | Use Antigravity CLI (`agy`) as the third agent instead of Gemini CLI, configured in `agents.yaml` plus one `antigravity-json` result parser; run it headless with `--mode accept-edits` and resume with `--conversation` | Google retired Gemini CLI for personal accounts on 2026-06-18 in favour of Antigravity CLI. Accept-edits approves only file edits, which ShareLane's guard and Git layers can police; a new output format is the one expected code extension point |
| 55 | Connect Antigravity through workspace `.agents/mcp_config.json` and `.agents/hooks.json` written by `init`; reuse the shared edit guard (taught Antigravity's `toolCall`/`workspacePaths` event and JSON `deny` reply); require one global `permissions.allow` rule `mcp(sharelane/*)`; add per-agent `workerNotes` telling Antigravity not to run commands | Antigravity's permission rules are global-only, so a narrow server-specific allow (like decision 31 for Codex) is the least privilege that lets headless workers use ShareLane. In print mode a refused command silently ends the turn, which the first real run proved, so the worker must be told up front |
| 56 | On Windows, resolve an npm `.cmd` launcher found on PATH to `node <script>` and spawn that, still without a shell | npm installs many CLIs only as `.cmd` launchers, which Node refuses to start without a shell; resolving them keeps decision 34's no-shell guarantee for any npm-installed agent |
| 57 | Keep a task's scope claim until the task ends even when the worker calls `release`; treat in-scope changes as claimed; treat `.sharelane/context/**` as ShareLane-managed (never an unclaimed or scope violation); unlink the `node_modules` junction before removing a worktree and clear such leftovers before a follow-up | The first real three-agent run showed a worker's routine `release` causing false unclaimed-edit notices, ShareLane's own map refresh flagged as a violation, and Git leaving the junction-only folder behind so a follow-up could not recreate its worktree |
| 58 | Record every agent run of a task (first run, replies, reassignments) in a `task_runs` table and report per-task totals of fresh input, cached input, and output. Normalize fresh input per CLI: Claude `input + cache writes`, Codex `input − cached`, Antigravity `input` (its cache reads are separate). Schema v5 rebuilds the tasks table once, with foreign keys off, to add the `needs_reassignment` status | One run's numbers hid the real cost of follow-ups and handoffs, and the CLIs count cache differently; a tested one-time rebuild is SQLite's only way to change a CHECK constraint without cascading deletes |
| 59 | Use the owner's existing rule (Cospire, 2026-09-26): hand off when the lowest usage window is at or below **7%** remaining. Each adapter names a built-in `quota` reader (`claude`, `codex`, `none`). "Could not tell" is never "fine" but does not block a start; a stale "plenty left" reading becomes "could not tell", while a stale "exhausted until reset" reading still stands. Codex is read from its local session logs; Antigravity has no reader | Reuses a rule already proven in practice and replaces proposal P8. Usage only rises until a window resets, so this asymmetry is safe; Codex's logs need no network or credentials; Antigravity exposes credits only interactively, so its limit errors are the signal |
| 60 | Read Claude's quota from a token-free status-line snapshot (`.claude/hooks/sharelane-statusline.mjs`, chained to the user's own status line, saved to `~/.sharelane/usage/claude.json`); when that is older than 15 minutes, fall back to Anthropic's undocumented OAuth usage endpoint. The sign-in token is read into memory, sent only to Anthropic, never printed or stored; the endpoint is called at most every 5 minutes; `SHARELANE_CLAUDE_USAGE_ENDPOINT=0` disables it. **Narrows DESIGN's "never touches auth tokens" rule for this single read-only check** | The owner chose "both" on 2026-10-02: the status line is official and token-free but only updates while Claude is open interactively; the endpoint (already proven in Cospire) keeps checks working when it is not, with Cospire's safeguards |
| 61 | Check allowance before every run. When a run fails with an allowance error (out of credits, usage or rate limit, 429), or the agent replies starting `HANDOFF:` after its own `usage` checkpoint, save the work to the task branch first, write `.sharelane/tasks/<task>.handoff.md`, and reassign automatically to the first configured agent that is outside the delegation chain, has not tried this task, and is not at its threshold; it continues on the same branch with the handoff as its prompt. Allow at most two reassignments; otherwise park the task as `needs_reassignment` and let the `reassign` tool hand it over (a person may pick any agent outside the chain) | Implements "a worker that hits its limit is taken over by another agent". Saving before the note follows the owner's rule that a handoff describing unsaved work is worse than none; the chain and tried-agent exclusions stop loops and ping-pong |
| 62 | Offer an optional per-task `budgetTokens` limit on fresh tokens (new input plus output) across all runs; warn the caller at 80% and, once used up, start no further run, reply, or reassignment. Keep the ~25% overhead target as workflow guidance | CLIs report usage only when a run ends, so budgets are enforced between runs. A trustworthy "direct run" baseline is not measurable, so an explicit budget is the enforceable control and the percentage target stays a guideline |
| 63 | At the owner's request, set Antigravity's global `toolPermission` to `proceed-in-sandbox` with allow rules for `git`, `node`, `npm` and deny rules for `git push`, `git reset --hard`, `rm`, `Remove-Item`; keep Antigravity's `workerNotes` telling headless workers not to run commands. `always-proceed` is left for the owner to choose | Its Windows terminal sandbox needs an administrator approval a headless worker cannot give, so headless commands are still refused and a refused command ends the turn. Turning on unsandboxed commands for another agent is a security choice for the owner, not ShareLane |
| 64 | Serve the dashboard with `sharelane dashboard` from Node's built-in `http` module: bound to `127.0.0.1`, answering only requests whose Host is `localhost`/`127.0.0.1` on its port, GET-only and read-only, with a strict self-only Content-Security-Policy and pages built from text nodes. The page polls every 2 seconds (pausing when hidden), and live output is read by byte offset from the task's own recorded log path | No dependency or build step is needed. The Host check blocks DNS rebinding, so other websites cannot read task data; read-only means looking can never deliver a notice or change a task; polling is simpler and more robust than sockets for a few local viewers; offsets stream output without resending large logs or trusting request paths |
| 65 | On the dashboard, read Claude's quota only from the saved status-line snapshot (never the token endpoint), cache quota and context freshness for 30 seconds, credit tokens to agents per recorded run, and show older tasks' saved usage as one run using the per-CLI fresh-input rules | A page that refreshes constantly must not touch a sign-in token or hammer the rate-limited endpoint; per-run attribution credits handed-off work to the agent that did it; the fallback keeps pre-Phase-5 history visible |
| 66 | Build the dashboard to the data-viz method: stat tiles for headline numbers, allowance meters with the 7% threshold marked, every status as icon plus label, a validated three-slot categorical palette for tokens by agent with a table view, separately selected dark-mode colors, and faded meters with "~" values when a reading is too old to trust | Colors never carry meaning alone, and the chart is readable for colour-blind viewers, in dark mode, and as a table; showing stale numbers as certain would contradict the "could not tell is never fine" rule |
| 67 | Give agents `run_check`: an owner-approved allow-list in committed `.sharelane/checks.json` (prefilled by `init` from package.json `test`/`typecheck`/`lint`, as the owner chose), run without a shell inside the caller's worktree with a timeout that stops the whole process tree, returning the last 8 KB of output. The list is always read from the project checkout, never the worker's editable worktree copy. Chosen (owner, 2026-10-03) instead of having Antigravity delegate terminal commands to another agent | Workers without a terminal (all delegated Claude workers, headless Antigravity) can verify their work for no tokens and see their own uncommitted edits. Reading the list from the owner's checkout stops a worker approving its own commands. It limits which command lines run, not what project code does, so it is explicitly not a sandbox. Delegating each command to another agent would cost a whole agent session per check and would not see unsaved edits |
| 68 | Publish ShareLane as an npm package (`sharelane`, MIT, copyright Manthan Kabra — the owner's choice) that ships its TypeScript source and runs it through tsx at runtime (`bin/sharelane.mjs` registers tsx in-process), with exactly four commands: `init [--yes]`, `mcp`, `dashboard [--port] [--open]`, `run <agent> <prompt>`, and a `files` allow-list | No build step, and the worker, schema, adapter file, and dashboard assets keep resolving from the installed package. The cost is tsx/esbuild as runtime dependencies (about 10 MB). `mcp` writes nothing but protocol to stdout |
| 69 | Generated MCP configs launch `node <bin> mcp`, with a project-relative bin path (`node_modules/sharelane/bin/sharelane.mjs`, or `bin/sharelane.mjs` in this repo) so committed configs work on any clone and inside delegated worktrees; fall back to an absolute path with a warning. Codex's global entry uses absolute paths. `init` never edits Codex's global config unless `--yes` is passed, and prints the `default_tools_approval_mode = "approve"` line as a manual step | MCP clients start servers without a shell, so Windows' `npx.cmd` cannot be used; `node` is a real executable. A user's global configuration is theirs to change |
| 70 | `init` detects `claude`, `codex`, and `agy` on PATH and wires each one found (Claude: `.mcp.json`, edit guard, status line; Antigravity: `.agents/` files plus the reminder of the global permission rule; Codex: the printed or `--yes` command), stays idempotent, merges existing settings, and prints Done / Skipped / Still to do. ShareLane also resolves npm's own `npm.cmd`/`npx.cmd` (`*_CLI_JS`) to `node <script>` | One command sets up a new project for whichever agents the user has. Without the npm fix, `run_check` could not start `npm test` on Windows without a shell |
| 71 | The dashboard opens on an **office view**: a pixel-art floor drawn in code on a canvas (no image files, so no art licensing), where each agent is an employee whose position shows its state — desk (working, or paused with Zz), review board (finished with changes in the last 6 hours), meeting room (needs a handoff or failed), lounge (free), sofa (out of allowance). | 72 | The dashboard can now **control** agents: `POST /api/tasks` (assign) and `/api/tasks/<id>/{pause,resume,stop,reply}`. Tasks assigned from the page have caller `you` | Controls are what the owner wanted from the UI. Token + Origin + JSON stops cross-site requests and DNS rebinding; the page still renders only text nodes |
| 73 | **Pause** stops the agent the same way cancel does (its work so far is committed to the task branch, claims released) but marks the task `paused` (schema v6) instead of `cancelled`. **Resume** queues a new run on the same branch: in the saved session if there is one, otherwise a fresh conversation that is given the original request again plus any note. Stop-and-continue keeps every change and works for all three agents. Schema v6 rebuilds the tasks table once to widen its status list, as v5 did |

## Proposed — need your yes/no

| # | Proposal | Why | Status |
|---|---|---|---|
| P1 | MCP is the main way agents talk to ShareLane, with a `sharelane` command-line tool as a fallback for agents without MCP | Not every agent supports MCP, but nearly all can run commands | Open |
| P2 | No always-running background program: each agent starts its own copy of the hub, and the copies share one SQLite database | Nothing to start or crash; downside is the hub can only reply, not push alerts | Open |
| P3 | Storage: SQLite for live state + markdown files for context (readable, committed to git) | Safe for several agents at once; context stays human-readable | Open |
| P4 | Search: SQLite full-text search; no AI-based "semantic" search in v1 | Semantic search needs an API key or local model | Open |
